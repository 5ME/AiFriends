## 轮次 1（v1 → v2）

**阻断 3 项**：

1. **合成模型错误（最重）**——CSS 的 alpha 合成发生在 **sRGB（gamma）分量空间**，v1 按"亮度空间线性混合"计算，导致结论整体偏悲观约一倍：纯白图顶部实测 4.16:1（v1 写 1.95:1 "基本不可读"）；连带使"单改蒙层或单改气泡都救不回来"的论证失效（K=1.5 顶部实测 5.61:1，本可达标）。
2. **`useChatSettings` 写成工厂函数**——违反 LD D-L7「模块级单例」，后果是两个消费方各持一份状态，开关整体失效。参照实现：`frontend/src/composables/useVoiceToggle.js:4`。
3. **reduced-motion 修法空转**——原计划用 `.loading-dots::before/::after { animation: none }` 停 daisyUI 的思考中指示器，但该动画位于 `mask-image` 内嵌 SVG 的 **SMIL** 中，`daisyui/components/loading.css`（5.5.17）内**没有任何 CSS animation / @keyframes / ::before / ::after**，规则完全无效。

**处置**：3 项全部采纳并重修（v2）。另采纳 13 项次要项（`grep` → `Select-String`、行号锚点、测试计数、`.msg-text-outline` 死类、`ring-white/60`→`/40`、文件数、`closeMic` 措辞、`7279335` 归属等）。

**拒绝 1 项**：行内 `code` 排除描边 —— 当时以"行内 code 仅 3.06:1，去掉描边会更难读"为由保留其描边。**该理由后被证明基于错口径**（见轮次 2 第 3 项），故轮次 2 一并翻转。

## 轮次 2（v2 → v3）

**须先修 3 项 + 流程违规 1 项**：

1. **W8 会把"伪原文"写进 spec（最重）**——v2 称"spec 原文要求 `pre` 与 `code` 都排除描边"，但 **spec 全文没有 `text-shadow` 条款，也没有 §3.4**（核实：该文件只有 `## 3. 已拍板决策`）。那句话实为 design v1 §3.4 自身的约定。→ **W8 作废**，改为 design 内部约定变更。
2. **§3.3 表 + 单测锁死了错底色**——第 2 行把 **95.625** 当作"纯白图最坏实际"，但 `95.625 = 255×0.75×0.5` 对应**气泡 α=0.5**，而本项目气泡是 α=0.35，**该值在合成链条里不存在**；真实最坏档是 **124.3125**（白图顶部），正确描边值 **18.63:1**（即 v1 的 18.63 原本是对的）。同时该表单位（0~1）与 §3.1（0~255）不一致。
3. **行内 code 的 3.06:1 系 sRGB 当线性亮度**——真值 **8.78:1**（最亮档）/ 14.79:1（最暗档）。W8 的唯一理由因此不成立，行内 `code` 改为**与 `pre` 一样排除描边**。
4. **【流程硬违规】门 2 批准前动了代码**——`c547e1e` 含 `frontend/src/utils/contrast.js` 与其单测，违反 `WORKFLOW.md` §2「用户点头前不许动任何代码」；且计划未同步（Task 1 仍全 `- [ ]`，头部仍写"已有 2 个文档 commit"，实际 3 个）。发生原因：我把用户"按你觉得更好的方案来吧"读成了实施授权，而门 2 需要的是**对方案的批准**。

**处置**：1~3 全部采纳并重修（v3）。第 4 项由用户 2026-09-11 裁决 **追认**（保留违规记录于 design §11.1，不回退重做）。

**同时修正的表述级问题**：W4 措辞（原文"≥4.5"在**原机制下成立**，是砍掉 §6.5 后才降到 4.16，故应写"依赖机制已被砍掉"而非"原文即错"）；简约模式深色底对比度 15.5 → **17.04**；E2 只做了"无背景图"未做 `@error`；回写清单遗漏 spec 9 行 / LD 14 行散落引用；L 档评审记录缺失；假依赖（"简约模式依赖描边已就位"）。

## 三轮共同暴露的模式（机制性修复）

三轮的错误同源，可归为两类：

1. **把 sRGB 数值当作线性亮度代入 WCAG 公式** —— v1 用错整个颜色空间，v2 又犯了两次（行内 code 3.06、深色底 15.5）。
2. **手写中间值而不从公式推导** —— 95.625 就是手写产物，且写错后又被锁进单测。

**机制性消除**：① 档位全部由 `bubbleBase()` / `overlaySrgb()` 推导，不手写中间值；② 单测内含**独立实现**的 WCAG 公式（不 import 被测模块）交叉验证；③ 源码注释固定写明"凡 0~1 的小数必须注明是线性亮度还是 sRGB 分量"。
