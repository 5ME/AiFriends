## 1. 背景与问题

当前聊天以 **360×600 固定尺寸弹窗（dialog）** 呈现，由角色卡片点击触发。经评审，存在以下问题：

1. **形态问题**：弹窗 = 无路由。刷新丢会话、无深链、浏览器后退无效、无法分享；桌面大屏空间浪费。
2. **实例问题**：每张角色卡片各挂一个 `ChatField` dialog（N 卡 = N 个常驻 DOM），每个 `InputField` 各自持有 MediaSource/Audio/VAD 实例。
3. **布局问题**：`ChatField.vue` 内全部使用 absolute 定位堆叠（头部 `absolute top-3`、消息区 `absolute top-18 h-112`、输入栏 `absolute bottom-4`），内容变化时会互相遮挡；应改为 flex column。
4. **可读性**：角色背景图铺满整个弹窗且无蒙层，消息直接浮在照片上，对比度不可控。
5. **消息细节**：每条消息重复显示头像+名字；无时间戳/日期分隔；`break-all` 切断英文单词；无 markdown；无"正在输入"指示与"停止生成"；无空状态。
6. **输入与语音**：单行 input + 绝对定位图标，长文本横向滚动；ASR 识别结果**直接发送**，用户无确认/修改机会；VAD 初始化失败（如权限被拒）时界面卡死在"语音初始化中…"，无错误态与重试。

### 1.1 关键约束：聊天背景图由角色创建者设定

- 创建/编辑角色时通过 `BackgroundImage.vue`（Croppie 视口 **300×500，固定 3:5 竖版**）裁剪。
- 聊天弹窗 `w-90 h-150`（360×600）恰好同为 3:5 —— 整条视觉链路是围绕**竖版角色肖像**设计的。
- 背景是创建者的**品牌资产**：不能粗暴裁剪（桌面 16:9 cover 会切掉 70% 构图），且创作者并非设计师，**文字可读性不能依赖图片本身**。

## 2. 设计目标与原则

| 原则 | 说明 |
|------|------|
| **微信骨架 × 角色世界** | 布局采用用户零学习成本的 IM 双栏结构（会话栏 + 聊天主区）；聊天区保留"走进角色场景"的沉浸式气质，不抄白底工作台。 |
| **尊重创作者构图** | 3:5 竖版肖像完整呈现，桌面端采用"舞台 + 角色之窗"而非全屏 cover。 |
| **可读性不依赖图片** | 文字区域一律落在确定性蒙层（scrim/glass）上；蒙层浓度按图片亮度自适应。 |
| **用户可降级** | 背景由他人设定，用户须能关闭沉浸模式（高对比/简约背景开关），也是无障碍刚需。 |
| **一个会话只有一个实例** | 聊天从"每卡一弹窗"收敛为"全站一个聊天页（路由驱动）"。 |
| **后端零依赖起步** | 复用 `get_list` / `get_history` / chat SSE / asr 即可完成主体；后端改动仅限可选项。 |

**三个层次：**

| 层次 | 职责 | 实现要点 |
|------|------|----------|
| **会话栏** | 微信式会话列表：头像 + 名字 + 最后消息预览 + 时间；选中态高亮 | 复用 `GET /api/friend/get_list/`（已按 `last_active` 排序） |
| **舞台** | 填充桌面剩余空间，维持氛围，不干扰阅读 | 同一张背景图 `filter: blur(40px) saturate(1.2)` + 黑色叠加层（浓度按亮度自适应），铺满聊天区 |
| **角色之窗** | 3:5 竖版"角色世界"：头部条 + 消息区 + 输入栏 | 清晰背景图 + 顶部到底部渐变压暗蒙层（`rgba(0,0,0,0→0.55)`）；窗口 `aspect-ratio: 3/5`，`max-w 420px`，高度 `min(85vh, 700px)`，圆角 24px + 投影 |

**移动端（<lg）**：会话栏收敛为抽屉（复用 NavBar drawer 交互模式）；角色之窗铺满全屏（去圆角），即今天弹窗的形态，但成为页面而非 dialog。

## 4. 路由与信息架构

### 4.1 新增路由

```
/chat/:friend_id/  →  name: 'chat-index'  →  views/chat/ChatIndex.vue   (needLogin: true)
```

### 4.2 进入路径（全部改为跳转聊天页，删除卡片内嵌 dialog）

| 场景 | 现状 | 改后 |
|------|------|------|
| 首页卡片直接聊天（`showDetail=false`） | 弹窗 | `router.push('/chat/:friend_id/')` |
| 好友列表卡片 | 弹窗（`showDetail=true` 时先开详情弹窗） | "开始聊天"按钮 → push 聊天页；详情弹窗保留 |
| 首页卡片（`showDetail=true`） | 详情弹窗 → "开始聊天" → 弹窗 | 详情弹窗保留 → "开始聊天" → push 聊天页 |
| 刷新/分享/后退 | 失效 | 天然可用 |
| 新会话 | — | 聊天页空状态（见 §7） |

> 会话栏未选中任何会话时（如直达 `/chat/123/` 不存在或首次进入）：会话栏照常显示，聊天区显示空态引导。

### 4.3 NavBar 适配

- NavBar 全局常驻（现状），聊天页隐藏**搜索框**（聊天页不需要全局搜索，避免视觉噪音；保留 logo/创作/用户菜单）。
- 抽屉侧栏在聊天页中与"会话栏"语义重叠：`lg` 以下聊天页自身提供返回按钮（→ `/friend/`），不再叠加 NavBar 抽屉入口。

## 6. 视觉规范

### 6.1 布局 tokens

| Token | 值 | 用途 |
|-------|----|------|
| `--layout-navbar-h` | 64px | NavBar 高度（现状） |
| `--sessionbar-w` | 280px（`lg` 以下抽屉化） | 会话栏宽度 |
| `--window-w` | min(420px, 92vw) | 角色之窗宽度 |
| `--window-ratio` | 3 / 5 | 角色之窗宽高比 |
| 消息区宽度 | 窗口内 `px-3`，气泡 max-w 75% | 在 420px 窗口内接近微信阅读宽度 |

### 6.2 蒙层/玻璃体系（核心）

| 层 | 规则 | 反例 |
|----|------|------|
| 窗口背景 | 清晰图 `cover` + 顶部 `rgba(0,0,0,.25)` → 底部 `rgba(0,0,0,.6)` 渐变 | 现状：无蒙层 |
| 舞台背景 | 同图 `blur(40px) saturate(1.2) scale(1.1)` + `rgba(0,0,0,.4~.6)` 叠加 | 现状：无舞台 |
| 头部条 | `bg-black/40 backdrop-blur` 玻璃条 | 现状：`bg-black/50` 圆形 pill，可读性尚可但零信息量 |
| 输入栏 | `bg-black/35 backdrop-blur rounded-xl` 玻璃悬浮条 | 现状：有，保留基调 |
| 己方气泡 | `bg-emerald-500/85 backdrop-blur` + 白字 | 现状：`chat-bubble-success` 不透明绿 |

**亮度自适应算法**（`useBackgroundAdaptive.js`，新）：

```
1. img 加载完成后 drawImage 到 16×16 canvas（跨域图用 crossOrigin=anonymous，
   加载失败则用默认值 K=1.0，不阻塞渲染）
2. avg = 像素均值亮度（0~1）
3. 覆盖浓度系数 K = clamp(0.6 + (avg - 0.5) * 1.8, 0.6, 1.5)
   —— 白图(avg≈0.9) → K≈1.32 深蒙层；黑图(avg≈0.1) → K≈0.6 浅蒙层
4. 同时计算主色 dominantColor（简单分桶直方图），供 accent 使用
5. 结果写入 CSS 变量 --overlay / --accent；fallback 前默认展示。（注：本表早前公式方向有误，已按 review P0-1 修正，最终数值以 spec §6.5 为准）
```

**用户侧开关**：头部条"简约背景"切换（`layout: 沉浸 | 简约`，localStorage 记忆）。
- 沉浸：如上。
- 简约：窗口背景替换为 `bg-base-100/95` 纯色 + 角色主色细边；舞台为纯 `bg-base-200`。消息可读性 100% 兜底。

### 6.3 色彩

| Token | 值 | 说明 |
|-------|----|------|
| `--accent` | 自动提取的角色主色（dominantColor），fallback `#10b981` | 语音开关激活态、己方气泡、选中态 |
| `--bubble-user` | `var(--accent)` 85% + blur | 随角色而不同的"对话氛围" |
| 文本 | 白/白 80% 系列（蒙层之上恒可用） | 保证 ≥4.5:1 |
| 引用 chips | `bg-white/15 text-white/90` | 与玻璃体系一致 |

### 6.4 字体与消息排版

- 消息正文 15px / 1.65 / `break-words`（替换 `break-all`）；AI 回复支持轻量 markdown（`marked` + `DOMPurify` 白名单：粗斜体、列表、行内代码、代码块带复制按钮、引用）。
- 标题/名字 14~16px；日期分隔线 12px 居中胶囊（`bg-white/10 text-white/60 rounded-full px-3 py-0.5`）。

## 7. 消息区状态设计

| 状态 | 表现 |
|------|------|
| 加载中 | 骨架屏：左右交替的圆角矩形 shimmer（2 对） |
| 空会话（首次） | 角色 `introduction`（半透明白大字）+ 3 个示例问题按钮（点击即发送）——通用兜底文案（"介绍一下你自己吧" / "讲个今天发生的故事" / "和我聊聊最近的烦恼"），示例问题由创建者自定义列为**后续可选增强** |
| 加载错误 | 窗口内居中"加载失败，点击重试"按钮（现状只有一行红字，无重试） |
| 流式生成中 | 首个 token 前显示三点跳跃动画（"正在思考…"）；生成期间输入栏右侧出现 **■ 停止** 按钮（现有 `abortController` 已支持，仅需 UI） |
| 生成结束 | 停止按钮消失，输入自动恢复 |
| 引用来源 | 消息底部 `[来源1]` 内联胶囊标签（点击展开该条来源详情）+ 消息尾部"📖 N 条参考来源"横排 chips（替代现有 collapse） |
| 消息分组 | 连续同 role 消息：仅首条带头像+名字，其后缩进气泡；日期分隔线按 今天/昨天/M月D日 |
| 时间戳 | 消息 hover 时气泡旁显示 `HH:mm` |

### 7.1 键盘与焦点

- Enter 发送 / Shift+Enter 换行；输入栏始终自动聚焦（进入页面 + 发送后）。
- Esc：正在聆听时取消音频；无弹窗可关。
- 所有图标按钮 `aria-label` + `data-tip` tooltip；焦点环 `focus-visible:ring-2 ring-white/60`；波形动画 `prefers-reduced-motion` 时静止显示。

## 8. 输入栏与语音流程（重点交互重构）

### 8.1 输入栏

```
[🎤]  ┌────────────────────────────────────────────┐  [➤ 发送 / ■ 停止]
      │  文本输入…（textarea 自动增高 1→4 行）        │
      └────────────────────────────────────────────┘
```

- textarea 自动增高（1~4 行，超过滚动）；Enter 发送、Shift+Enter 换行；空内容发送键置灰（`disabled` + opacity）。
- 发送键 → 流式期间变为"■ 停止"（点击 `abortController.abort()` 并结束 TTS）。

### 8.2 语音流程（核心变化：识别结果先回填、确认后发送）

```
点 🎤 → 输入栏进入"聆听态"：波形动画（真实音量驱动，现有 32 条 CSS 定时器改为
        AnalyserNode 数据驱动）+ "正在聆听…" + [Esc 取消]
  → 语音结束 → VAD → ASR → 识别文本回填到 textarea（可编辑！）+ [➤发送] 恢复可用
      ├─ 用户按 Enter / 点发送 → 发送（与文本路径完全一致）
      └─ 用户点 🎤 再录 → 替换回填内容
  → ASR 失败 / 权限被拒 / VAD 初始化失败：
      输入栏内联错误提示（红色小字）+ [重试] 按钮 —— 不再卡死在"语音初始化中…"
  → 可选开关（设置项，默认关）：自动发送 —— 识别完成即发送
```

- 语音输入期间若正在播放 TTS，`onSpeechStart` 先停音（现状已实现，保留）。
- 麦克风权限提示：首次点击引导浏览器授权；拒绝后给出明确指引文案。

## 10. 实施计划（分阶段 + 验收标准）

### Phase 1 —— 骨架（形态之战）

**改动：**
1. 新增路由 `/chat/:friend_id/` + `views/chat/ChatIndex.vue`；
2. `SessionList` / `SessionItem`（复用 `get_list`）；
3. `ChatWindow.vue`：flex column（头部条 / ChatHistory / InputField），3:5 窗口 + 舞台背景；
4. `Character.vue` / `CharacterDetail.vue`：删除内嵌 `ChatField`，改为 `router.push`；
5. `ChatField.vue` 下线或保留为移动端薄壳；
6. NavBar 聊天页隐藏搜索框。

**验收：** 首页/好友列表点卡片 → 跳转聊天页；刷新不丢会话；后退返回到来源页；全站只有一个聊天实例（Vue DevTools 组件树验证）；`lg` 以上双栏、以下抽屉。

### Phase 2 —— 消息打磨

**改动：** ChatHistory 骨架屏/空状态/错误重试；Message 分组 + 日期分隔 + hover 时间 + 引用 chips；备注 markdown 渲染（`marked` + `DOMPurify`，替换 `break-all` 为 `break-words`）。

**验收：** 新会话空状态含 introduction + 3 示例问题；连续消息仅首条带头像；图片来源消息显示引用 chips；代码块可复制。

### Phase 3 —— 输入与语音

**改动：** InputField textarea 化 + 停止生成；Microphone 错误态/重试 + 音量驱动波形；识别文本回填确认。

**验收：** 长文本不横向滚动；流式中出现停止按钮且可中断（TTS 同步停止）；麦克风拒绝授权时出现指引而非静默卡死；语音识别结果先回填、编辑后发送。

### Phase 4 —— 自适应与质感

**改动：** `useBackgroundAdaptive.js` 亮度/主色提取；蒙层浓度与 `--accent` 接入；"简约背景"用户开关；创建页预览 + 亮度提示；无障碍细节（aria/tooltip/reduced-motion）。

**验收：** 白色/黑色/高饱和背景图下文字对比度均 ≥4.5:1；开关双向生效；创建页可预览聊天效果。
