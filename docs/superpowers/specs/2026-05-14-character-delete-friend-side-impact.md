# 角色删除对好友侧的体验影响 — 改进方案

> 设计日期：2026-05-14 | 状态：方案 A 待实施，方案 B/C 待讨论

## 背景

角色被创作者删除后，CASCADE 级联删除所有 Friend 和 Message。已在聊天页面中的好友侧用户在不知情的情况下发送消息，chat API 返回 404，但前端仅 `console.log` 错误，用户看到的是沉默失败。

**当前链路（方案 A 要解决的问题）：**

```
好友 B 发送消息
  → POST /api/friend/message/chat/ { friend_id: X }
  → Friend.objects.filter(pk=X) → 无结果（已 CASCADE 删除）
  → 返回 404 {"message": "好友关系不存在"}
  → streamApi.js onopen: 非 SSE，抛 Error
  → InputField.vue onerror: console.log(err) ← 用户不可见
```

## 方案对比

### 方案 A：最小 — 404 错误前端可感知

好友 B 收到一条红色气泡提示"角色已被删除，相关好友关系已解除"，聊天框保持打开（用户可自行关闭）。

**改动范围：**
| 文件 | 改动 |
|------|------|
| `backend/.../chat/chat.py` | 404 响应增加 `detail` 字段 |
| `frontend/.../InputField.vue` | onerror + catch 中 emit 错误气泡 |

**代价：**
- 约 30 分钟，2-3 个文件
- 无数据模型变更

**收益：**
- 用户不再面对沉默失败
- 可立即交付

**限制：** 聊天记录已随 CASCADE 丢失。

---

### 方案 B：中等 — 角色软删除 + 聊天记录只读保留

角色删除时不物理删除，改为标记 `is_deleted=True`。已有好友：
- 可查看历史聊天记录
- 不可发送新消息
- 角色在发现/搜索中隐藏

**改动范围：**
| 层级 | 改动 |
|------|------|
| 数据模型 | Character 加 `is_deleted` 字段 + migration |
| 后端 | 所有 Character 查询处过滤 `is_deleted=False`（首页、用户空间、好友列表等 ~6 处） |
| 后端 | chat.py / get_or_create.py 等加角色状态检查 |
| 后端 | remove.py 改为软删除 |
| 前端 | 好友列表中被删除角色的展示（灰显/标记） |

**代价：**
- 约 1-2 天
- 数据模型变更 + migration
- 需确认：Character 模型 __str__ 等无关方法是否受影响

**收益：**
- 聊天记录得以保留
- 好友侧损失降为"不能再聊"，而非"全没了"

**限制：** 数据库积压（SQLite 下影响有限）。创作者无法真正删除数据。

---

### 方案 C：彻底 — 软删除 + 已有好友继续可用

在方案 B 基础上，Friend 关系不随角色删除而失效。角色"下线"后：
- 新用户不可见、不可搜索、不可添加
- 已有好友可继续聊天
- 创作者可下线但不可抹掉他人聊天记录

**改动范围：** 方案 B 的全部改动 + 额外调整：
- chat.py / memory agent 等聊天链路不再依赖角色-is-deleted 检查
- "我的角色"管理页增加"下线/上线"操作
- 角色删除 UI 文案调整（"删除"→"下线"）

**代价：**
- 约 3-5 天
- 触及产品核心逻辑——角色归属权在添加好友后部分让渡
- 回滚困难，需要明确的产品决策

**收益：**
- 好友侧完全不受影响
- 代表最成熟的产品行为

**限制：** 需要产品层面决策，不可纯技术推动。

---

## 推荐路径

**先 A 后 B。** A 没有坏处，是当前删除确认弹窗（创作者侧保护）在好友侧的自然补充。B 需要产品决策后再启动。
