## 3. 1.5.1 — Redis 限流中间件 (P0)

### 3.1 算法选择：Sliding Window Log

| 算法 | 准确性 | 内存 | 实现复杂度 | 适合场景 |
|------|--------|------|-----------|---------|
| Fixed Window | 低（边界突发） | 低 | 简单 | 不推荐 |
| Sliding Window Log | 高 | 中（窗口内请求数） | 中等 | **本次选择** |
| Token Bucket | 中 | 低 | 较高 | 持续高吞吐 |
| Sliding Window Counter | 中高 | 低 | 较高 | 大规模 |

选择 Sliding Window Log 的理由：
- 面试可讲清楚算法原理（Redis Sorted Set + Lua 原子操作）
- 每分钟 5-20 次请求，窗口内数据量极小（≤20 条），无内存压力
- Retry-After 计算精确（最早过期记录的时间戳）

### 3.2 限流规则

| Scope | URL 前缀 | Methods | 限制 | 说明 |
|-------|---------|---------|------|------|
| `login` | `/api/user/account/login/` | POST | 5/min | 防暴力破解 |
| `register` | `/api/user/account/register/` | POST | 3/min | 防滥用注册 |
| `chat` | `/api/friend/message/chat/` | POST | 20/min | 主要 AI 成本来源 |
| `asr` | `/api/friend/message/asr/asr/` | POST | 10/min | 语音识别成本 |
| `upload` | `/api/document/upload/` | POST | 10/min | 文档处理成本 |
| `default` | `/api/*` 其他 | POST/PUT/PATCH/DELETE | 60/min | 通用 API 保护 |

GET 请求不限流，避免误伤正常的列表查询。只对有副作用的写操作做限制。

规则配置在 settings.py 中，4 元组格式——`(url_prefix, methods, max_requests, window_seconds)`：

```python
RATE_LIMIT_RULES = {
    'login':    ('/api/user/account/login/',        ['POST'], 5,  60),
    'register': ('/api/user/account/register/',      ['POST'], 3,  60),
    'chat':     ('/api/friend/message/chat/',        ['POST'], 20, 60),
    'asr':      ('/api/friend/message/asr/asr/',     ['POST'], 10, 60),
    'upload':   ('/api/document/upload/',            ['POST'], 10, 60),
    'default':  ('/api/',                            ['POST', 'PUT', 'PATCH', 'DELETE'], 60, 60),
}
```

阈值后续可通过环境变量覆盖（`RATE_LIMIT_LOGIN_MAX=5` 等），方便生产环境不重启调整。第一版先硬编码在 settings.py 中。

### 3.3 用户识别

```
request.user.is_authenticated ？
  ├── Yes → key = f"ratelimit:user:{user_id}:{scope}"
  └── No  → key = f"ratelimit:ip:{client_ip}:{scope}"
```

Client IP 从 `X-Forwarded-For` header 获取（兼容反向代理），fallback 到 `REMOTE_ADDR`。

### 3.4 Redis Lua Script

一条 Lua script 完成 check + add + trim + ttl，保证原子性：

```lua
-- KEYS[1]: ratelimit key
-- ARGV[1]: current timestamp (ms)
-- ARGV[2]: window size (ms)
-- ARGV[3]: max requests
-- ARGV[4]: unique member id，Python 侧用 f"{now}:{uuid.uuid4().hex[:8]}" 生成
--          必须唯一——同一毫秒内多次请求如果 member 相同，ZADD 只会更新 score，不会新增记录

local key = KEYS[1]
local now = tonumber(ARGV[1])
local window = tonumber(ARGV[2])
local limit = tonumber(ARGV[3])
local member = ARGV[4]

-- 清理窗口外的旧记录
redis.call('ZREMRANGEBYSCORE', key, 0, now - window)

-- 当前窗口内请求数
local count = redis.call('ZCARD', key)

if count < limit then
    -- 放行：记录本次请求
    redis.call('ZADD', key, now, member)
    redis.call('EXPIRE', key, math.ceil(window / 1000) + 1)
    return {1, limit - count - 1}  -- {allowed, remaining}
else
    -- 拒绝：计算 Retry-After（最早记录过期时间 - 现在）
    local oldest = redis.call('ZRANGE', key, 0, 0, 'WITHSCORES')
    local retry_after = math.ceil((tonumber(oldest[2]) + window - now) / 1000)
    if retry_after < 1 then retry_after = 1 end
    return {0, retry_after}  -- {denied, retry_after_seconds}
end
```

返回值：Lua table `{status, value}`
- `status=1`: 放行，`value=remaining`（剩余可用次数）
- `status=0`: 拒绝，`value=retry_after_seconds`

### 3.5 Redis 连接

```python
# 使用独立的 Redis DB（/1），与 Celery broker（/0）隔离
REDIS_URL = os.environ.get('REDIS_URL', 'redis://localhost:6379/1')
redis_client = redis.Redis.from_url(REDIS_URL)
```

**为什么不用 Django Cache Framework？** Django 的 Redis cache backend 不支持 Sorted Set 操作（`ZADD`、`ZREMRANGEBYSCORE`、`ZCARD`），而这些是 sliding window 算法必需的。直接用 `redis-py`。

### 4.2 写入策略：直接写入 + try/except

**不使用 Celery 任务**，理由：
- 单条 INSERT 耗时 < 1ms，不会阻塞请求
- Celery 任务序列化/反序列化开销更大
- Celery Worker 可能未运行，导致数据丢失
- 用 `try/except` 包裹，写入失败只记日志，不影响主流程

#### 4.3.3 Embedding — 在 `embeddings.py` 中采集（逐 batch 记录）

`embed_documents` 每 10 条文本调用一次 API。**选择方案 A：逐 batch 记录**——每个 batch 是一次独立的 API 调用，记录粒度匹配计费粒度，适合做成本分析。

按当前逻辑，一次 50 条文本的文档处理会生成 5 条 `APIUsage` 记录（每 batch 一条）。

这里有一个难点：`embed_documents` 没有 `user_id` 参数。调用方有两类：
- **Celery 文档处理任务**（`process_document_task`）— user_id 已知，但没有请求上下文
- **Chat Agent 的 `search_knowledge_base` tool** — user_id 在 state 中

方案：给 `CustomEmbeddings` 加一个可选的 `user_id` 属性：

```python
class CustomEmbeddings(Embeddings):
    def __init__(self, user_id=None):
        self.user_id = user_id
        ...
    
    def embed_documents(self, texts):
        start = time.time()
        try:
            response = self.client.embeddings.create(...)
            token_count = response.usage.total_tokens
            duration_ms = (time.time() - start) * 1000
            if self.user_id:
                record_api_usage(user_id=self.user_id, api_type='embedding',
                                 model_name='text-embedding-v4', token_count=token_count,
                                 duration_ms=duration_ms, success=True)
        except Exception:
            if self.user_id:
                record_api_usage(user_id=self.user_id, ..., success=False, ...)
            raise
```

调用方修改：
- `graph.py` search_knowledge_base: `CustomEmbeddings(user_id=state["user_id"])`
- `process_document_task`: `CustomEmbeddings(user_id=user_id)`
- 系统知识库导入脚本：`user_id=None`（不记录）

### 4.4 record_api_usage 工具函数

放在 `backend/web/utils/usage.py`：

```python
def record_api_usage(*, user_id, api_type, model_name,
                     token_count=0, duration_ms=0,
                     success=True, error_message=''):
    """记录 AI API 调用用量。写入失败不抛异常。"""
    try:
        from web.models import APIUsage
        APIUsage.objects.create(
            user_id=user_id,
            api_type=api_type,
            model_name=model_name,
            token_count=token_count,
            duration_ms=duration_ms,
            success=success,
            error_message=error_message,
        )
    except Exception:
        logger.exception('APIUsage 写入失败: user=%s, type=%s', user_id, api_type)
```

## 6. 风险与缓解

| 风险 | 缓解 |
|------|------|
| Redis 不可用时限流中间件阻断所有请求 | **fail-open**：Redis 连接异常时跳过限流，记录 ERROR 日志 |
| APIUsage 写入拖慢请求 | try/except 包裹，失败不重试 |
| Embedding `user_id` 改动影响多个调用方 | 默认 `user_id=None`，向后兼容 |
| Chat Agent usage 数据不准确（streaming 分 chunk 到达） | `stream_options.include_usage=True` 已在用，汇总所有 chunk 的 token 数 |
| 迁移文件编号冲突 | 先检查 `web/migrations/` 最新编号，按序递增 |
